# Changelog

本项目从 1.3.0 开始遵循语义化版本，并使用统一的 `vX.Y.Z` Git 标签。

## [Unreleased]

## [1.11.0] - 2026-10-05

### Fixed

- HTM 在活动搜索层及时验证并采用新候选上界，分别记录接收、验证与采用。只有可靠下界与上界相遇才确认最短；取消、原始期限到达和未完成层不产生完成证书。
- 内部候选上界及时传给证明器，页面仍在候选预算结束后发布，HTM 提前交付默认保持关闭。

### Changed

- 合并 HTM Phase-1 对称映射，减少映射内存和查询开销；完整 Phase-1 + Corner、无 edge PDB 配置使用专用展开路径，其他配置保留通用路径。
- 新增版本化、完整校验的 HTM 对称映射启动缓存与独立 Phase-2 缓存；离线准备和安装校验覆盖两项新增资产。
- HTM 默认使用原生六方向两阶段候选器，保持一个候选线程、1.5 秒总预算及与证明共享的请求额度。HTM 半转仍计一步，HTM/QTM 距离表独立。
- 正逆方向选择使用根下界和有界采样，取代完整重复探测；采样不计入完成层证明，期限和切换次数有界。

### Tests

- 六个冻结照片状态共 36 次新旧真实 HTTP 请求，30 秒期限、15 总额度：严格最短完成数 11/18→15/18，PAR-2 平均耗时下降 38.9%，没有新增超时。结果只适用于本次样本，initial-16 仍三次超时。
- 分别保留映射、专用展开、启动缓存、单方向/六方向候选消融，以及迟到候选、损坏缓存、停止竞争、低额度和独立公式回放证据；详见 `docs/htm-speed-optimization-report-2026-10-05.md`。
- HTM 独立强表本轮仅完成设计，尚未生成或加入发布包；两个引擎仍为 Portable x64 O3/LTO、非 PGO 构建。

## [1.10.1] - 2026-10-03

### Fixed

- HTM 候选与证明共享请求线程额度；候选结束后仅在完整搜索层边界恢复证明额度。补齐候选搜索、表加载/构建的取消与原始期限检查，防止旧任务回调更新已结束的结果。
- QTM 对称坐标初始化加入有界暂停检查，修复浅请求结束后 loader 不能及时暂停而触发资源回收失败的问题。

### Changed

- 增加候选产生/交付、严格最短确认、线程额度和原生内存峰值记录，便于区分交付等待与证明耗时。
- 保留本轮速度实验为显式开关：HTM 提前交付默认关闭，QTM 专用展开默认关闭，方向候选仍用 legacy，late Tail 默认关闭；完整 strong/Tail 资产继续正常使用。
- 两引擎补齐 Portable PGO 构建与独立训练支持；本次发布仍使用普通 Portable O3/LTO，未训练或启用 PGO。

### Tests

- 补齐六组三阶照片、合法状态和独立公式回放，保留 72 次新旧实验包对照及全部超时/失败记录。
- 本次为资源管理与诊断维护版本，不宣称默认求解速度提高。实验包有可重复的单状态退化；保守默认包的 HTM initial-1 仍曾在 30 秒内无法证明最短，后续需要独立排查。

## [1.10.0] - 2026-10-01

### Changed

- QTM 升为正式功能，页面与能力接口取消实验标记；Windows 默认便携包集成完整 HTM 与 QTM。
- 源码发布只含活动代码、构建/生成工具和文档；不含预生成表、缓存或运行环境，也不再要求下载便携包导入资产。GitHub 自动源码快照通过 export-ignore 排除测试和报告。
- README 重写为逐步本地安装手册，详细说明工具安装、编译、主表/强表/Tail/二阶距离表/坐标缓存生成、续建和 19 项完整资产校验。
- QTM 完整配置先校验自己的基础表并生成候选；私有 HTM 辅助表改为缺表或损坏时按需回退，不再常规映射。
- QTM 默认采用候选先行、强表优先的证明调度，强表加载期间基础证明累计限制为 0.3 秒；保持原 deadline，未完成窗口不签发证明。校验配额最多 8 线程并受请求总额度约束。
- v4 强表校验按块使用局部累积结果，保留逐字节 FNV 与全部 nibble 范围校验；记录初始化、等待、旧配置退出与实际采用时点。
- QTM 后台任务容量和终态保留时间有界；等价活动请求共享原期限，不同 timeout 分开处理。页面展示候选成本、已证下界、差值和真实阶段耗时。
- 二阶 QTM 能力不再依赖三阶原生资产；三阶区分包内资产、验证就绪与实际采用配置。

### Tests

- 增加独立 QTM Portable CI、浅层四分之一转 BFS oracle、原生协议与中断门禁；完整强表和损坏资产检查使用显式发布验收门禁。
- 前期候选包及参考机测量记录见 `docs/qtm-production-upgrade-report-2026-10-01.md`。正式状态按本次发布调整，前期报告保留原测试时点；不据两个实拍样本宣称普遍性能或固定时间保证。

## [1.9.0] - 2026-09-30

### Changed

- QTM 按请求管理 staged loader 的校验额度与内存接纳；默认加载校验 4 线程，与候选/证明共享总额度。
- QTM 默认有界复用单个已校验进程，闲置 20 秒；loader 确认暂停、代际保护、内存超限和 HTM 优先关闭均有独立验收。可用 `CUBE_QTM_REUSE=off` 恢复立即释放。
- 加入独立的 strong 升级重跑、冗余 slice 省略和有效 strong-first 预取开关；本轮收益不足的搜索策略默认关闭。
- Windows 资产清单包含实际版本、原生 build-info 与当前应用源码 SHA-256。
- 正式发布完整 HTM 稳定包、QTM 强配置实验包、精简源码包和下载 SHA-256；包内不含测试、基准报告或开发构建目录。
- 用户说明增加同版本便携资产导入、全资产校验和 QTM 完整强表启动入口；普通分阶段加载与 eager 完整加载的差异明确说明。
- CI 将稳定 HTM 与共享代码的 70% 分支覆盖率门禁迁移到实际运行模块，QTM 保留独立功能与生命周期验证；标签检查成功后只准备草稿，完整附件验收后再发布。

### Fixed

- QTM 的无限期限贯穿二阶、三阶、排队、原生求解和 Python 回退；HTM 的资源等待计入同一请求预算。
- 生命周期测试改为绑定隔离后的 HTM 模块，候选到达立即唤醒 HTTP 等待。
- 分开记录 base、strong、Tail 就绪与快照采用、原生搜索、请求和资源占有时间；完整清理先于资源放行。
- wheel 包含所有求解器子包，并在 CI 中检查隔离安装后的导入。
- HTM 支持 Portable 构建，正式打包检查二进制、来源散列和通用 x64 编译模式。

## [1.6.0] - 2026-09-29

### Added

- 三阶 QTM 原生候选搜索、专用 Corner / Phase-1 距离表和 QTM Tail-7；强配置可加载三轴联合表及 Tail-8。

## [1.5.0] - 2026-09-28

### Added

- 二阶和三阶可选 HTM / QTM 计步；默认 HTM，QTM 下 180° 动作计 2 步，搜索优化动作总代价。
- 二阶 QTM 完整准确距离表，覆盖 3,674,160 个状态、最大距离 14；双模式磁盘与内存缓存隔离，并随 Windows 包发布。
- 前端模式切换取消旧任务、拒绝迟到响应并保留照片与人工校正；预算不足明确显示尚未证明最短。

### Changed

- 原生常驻协议升级为 protocol 3 / proof 2，声明 HTM、QTM 能力；候选、证明进度与任务缓存均按模式计价与隔离。
- QTM 严格搜索复用 HTM 剪枝下界并禁用 HTM Tail 捷径；默认完整预算为二阶 14、三阶 26。
- Windows 发布预检验证双模式原生协议并生成、校验与复制两张二阶距离表。

## [1.4.0] - 2026-09-27

### Added

- 二阶准确 HTM 距离表，覆盖整体旋转规范化后的 3,674,160 个状态，最大距离 11；缓存带版本和 SHA-256 校验，并随 Windows 便携包发布。
- 原生性能基准、独立 PGO 训练状态和重构验收记录，分别记录启动、证明深度、候选解和线程统计。

### Changed

- 三阶原生搜索采用紧凑棱排列、三轴同值加强下界、分阶段展开和完整 PDB 下的小表查询省略。
- 优先启动原生严格证明；困难状态同时生成快速解，并把新候选传给活动搜索以收紧上界。
- 原生服务支持任务 ID、协作取消和进程内已完成证明深度复用；重复活动请求复用同一任务。
- 排队、初始化、搜索及 Python 回退共享绝对截止时间，页面分别显示解生成与证明耗时。

### Fixed

- 无限时任务使用原生核心，排队任务可立即取消，原生服务异常会记录回退原因。
- 二阶缓存使用源码或冻结应用的运行目录，保持便携版路径一致。
- 原生命令行、环境变量和缓存构建使用 Unicode 路径，支持中文目录、空格和表情符号。
