## 3. S0：冻结小规模、有效的性能基线

复用当前 Portable O3、同资产、15 个工作线程的配置，保留 strong-first。纯证明诊断关闭候选和证明缓存、固定正向、dual off、同初始上界；端到端诊断使用生产候选与默认 staged。

现有 pgo16 成本 17、known18 成本 18 继续作快速回归。主吞吐诊断优先在 pgo16 上校准成本 19，单次最多 5 秒；历史记录已使用过这一成本，但当前纯证明配置仍需确认。目标是选择能在约 0.5–3 秒内**完整排除**的成本层。

known18 的严格 QTM 最短为 20，不能将成本 20 找到解即停止的总耗时用作固定树比较。若现有状态无法提供合适层，最多加入两个已冻结的诊断状态；其中一个可选既有方向退化样本 legal-20271018。先校准再冻结 facelets、成本、hash，不能按候选优化成绩挑选样本。

每个机制只比较“最新基线 + 一个变体”，每配置每状态 3 次、每次最多 5 秒。采用交错配对顺序并保持机器负载相近。超时或找到解的层不进入完整树吞吐表；降一个可达成本后同时冻结基线与变体。

记录完成成本、生成量、原生墙钟、每百万生成候选耗时、查询/拒绝数、方向与探测耗时。方向和新增剪枝允许生成量减少；纯坐标省略应保持主要生成量与下界判定一致。

## 4. S1：及时采用 strong，控制首次请求的加载竞争

优先处理首次请求；有界复用只能节省后续请求，不能解决首次强表接入。

### 4.1 先取得采用延迟证据

用 initial-1 默认 staged 做一次 15 秒诊断，记录 strong ready/adopted、当时证明成本、该层已用时间、剩余期限、快照身份和生成量。若 strong 仍未 ready 或缺少采用记录，可将**这一项**延至最多 30 秒，保留失败原因；不扩成重复长验收。

基线与最终接入变体各运行一次，复用基线记录。加载与搜索重叠，不相加阶段时间；终态超时时保留已完成层，未完成层不生成证书。

### 4.2 先控制 loader 与证明的并发额度

当前 strong nibble 已按 64 MiB 块、最多 8 线程并行校验（strong_pdb.cpp:217–263），不是待实现的功能。staged loader 与请求的 15 线程额度独立，因此可能同时争用 CPU 和内存。

新增可配置的校验线程预算，并记录 loader、candidate、proof 实际活动线程。比较当前策略与一个总高负载线程受控的策略；例如总额度 15，在校验期给 loader 4、candidate 1、proof 10，strong 就绪后再归还额度。这里只是待测配置，不预设它一定更快。

只比较同一 cold/staged 请求的首候选、strong ready、完成成本与请求墙钟。工作线程调整发生在安全调度点；后台 loader 空闲时不占用证明额度。

### 4.3 有显著采用等待时，试验一次 strong 升级重启

当前只在成本层边界采用快照（solver.cpp:1790）。如果已验证 strong 到达后长时间未采用，在现有低频控制检查点加入独立的升级信号：

1. 区分升级、用户取消与超时；停止旧 worker 并等待退出。
2. 保留此前完整排除层和已重放验证的候选；当前未完成层只保留统计，不作为覆盖证明。
3. 原子切换已完整校验的快照，重建正/逆根坐标、根下界和坐标需求；同层 TT 等状态按新快照重建或清空。
4. 在同一绝对 deadline 内，从根重跑当前成本层。strong 可提高合法根下界；不得把中断的遍历写成完整层证书。
5. 每请求最多一次 strong 提前重启；Tail 先继续在层边界采用，避免连续重启。

记录丢弃的生成量、停止/重建开销和实际采用延迟。候选目标为 ready→采用不超过 0.5 秒，且请求完成成本/墙钟优于等待层边界；这是验收目标，不是预期加速承诺。若当前层很快完成或剩余期限不足，继续原策略。

## 5. S2：完整 strong-first 专用热路径

- base、部分表、legacy/interleaved、小表预筛需要时保留现有路径。
- sorted_slice、twist/flip、角排列以及接受节点后续需要的字段继续正确维护。

验证 QTM 的现有浅层独立 oracle、接受节点 materialize、各 cutoff 下的接受/拒绝等价，并覆盖完整 strong、部分表、base 配置。注意现有部分 Python native 测试已迁至 HTM，不能把它们的通过当作 QTM 新路径验证。

## 6. S3：可上线的有界进程与资产复用

初始候选策略为闲置 TTL 20 秒、单个 resident QTM；关闭策略仍可配置。实际收益测两个**不同**浅状态，或在诊断中关闭证明缓存，分离热加载与同状态缓存。

状态机：

```text
COLD → STARTING → BUSY → IDLE → BUSY
任何状态遇到 HTM / TTL / 内存超限 / 故障 / 资产配置变化
    → EVICTING → COLD
```

实现要求：

- CPU lease 与 resident 进程登记分开。释放请求 CPU 后，broker 仍知道 idle QTM 的关闭入口；HTM 先阻止新 QTM 接入，再抢占 idle/BUSY 进程。
- 单个 service controller 串行管理进程、请求和退出。进程 generation_id 与 request_id 分开；旧 TTL、旧 reader、旧清理任务不能操作新进程。
- 常驻事件 dispatcher 消费服务级 ready/asset_ready 与请求事件。当前只在 solve 循环消费的方式，不足以管理 idle loader。
- 请求结束后 loader 必须已完成或在分块检查点暂停并确认。idle 不继续无额度地校验 strong/Tail；下一 QTM 请求获取额度后再恢复。无法安全暂停时，该请求结束仍退出进程。
- 仅保留同进程内已完整校验的只读资产对象。重新打开资产仍完整校验；不能用 mtime、size 或 manifest 替代强剪枝数据校验。
- 退出与 reader 清理完成后才报告资源已让出，保留当前已修复的清理顺序。

内存策略按 profile 区分。原型 1 GiB 仅适合约 565.5 MiB 的 base 场景；strong nibble 主体约 1.64 GiB，叠加 base/Tail 后完整工作集明显更大。不能将 1 GiB 原型直接用于保留完整强资产。

base idle 可先用 1 GiB 候选上限；strong idle 上限依据本机实测工作集与系统可用内存冻结。内存不足时立即释放，默认不主动预热。进入新加载阶段前先做内存接纳判断，连续采样工作集、private bytes 和系统可用内存，避免仅检查 private bytes 遗漏文件映射。

真实等待完整 TTL，覆盖 loader 未完成、strong 已加载、idle→HTM、BUSY→HTM、快速新请求与旧 TTL 竞态。目标：第二个不同浅状态消除至少 80% 初始化开销、HTM 额外等待仍≤1秒、无持续内存越界和残留 loader。未达标则保留立即释放默认。

## 7. S4：减少方向探测开销，降低误选风险

保留合法全局根下界 max(h(s), h(s⁻¹))；将“下界更强”与“该方向更省工作”分开。现有逆态根下界更大就直接选逆向、浅层截断采样按拒绝率选方向，均需要在困难完整层验证。

建议先实现两个独立实验：

1. 短任务跳过探测；探测预算与预测的证明工作量关联，而不是仅按用户允许的 timeout 分配。使用上一完整层的实际时间/增长、快照和任务规模，避免困难程度小却有长 timeout 的请求支付固定开销。
2. 困难任务对多个固定根前缀做均衡采样，比较存活子树工作量、查询成本和耗时；样本不足或差异接近时采用稳定默认。

当前 sample_direction 不包含 Tail、候选、BPMX、TT（solver.cpp:854–895），不能把其拒绝率直接视为完整深层成本预测。强表采用后重新评价方向，完整层边界才切换；提前切换须从根重启。

最多两个困难诊断状态比较 off/bounded/新策略，不针对单个 facelets 写特例。方向收益计入探测总开销与 deadline；只有同成本完整排除的墙钟改善且无明显个案退化，才改变生产默认。

## 8. S5：便宜 selective dual；更强 PDB 设进入条件

仅在 S1–S4 结果明确后推进额外剪枝。当前 dual 会重建逆态、依次查询 Phase-1/Corner/单轴 strong，无 cutoff（solver.cpp:502–534）。

先做小改动：传入 remaining，合法逆态下界足以拒绝后立即结束；完整 strong 下省掉同轴被支配的 Phase-1；单独比较 inverse strong-first 与 Corner-first。随后试验 slack 0/1、较深任务根或有额外拒绝收益的区间触发。

计入逆态提取、PDB 查询和新增拒绝成本；生成量下降但墙钟变慢不启用。只有 profiling 确认逆态提取仍主导，才研究专用/增量逆态坐标。逆态转移涉及左乘，不能直接复用正态右乘规则；各合法下界取最大值。

有效预取、父节点强轴优先等放到独立后续消融：先实现实际执行路径和计数，再比较；不得破坏三轴相等加强及接受节点必要字段。强表校验若仍主导冷启动，再分解 checksum、范围/max、对称表与缺页成本，试验线程预算或实现优化；保留完整校验与当前格式兼容。

只有困难请求已及时采用完整 strong，且瓶颈仍主要来自完整成本层树规模，才研究互补七棱块投影。未归约位置+朝向为 12P7×2^7=510,935,040 项，byte 主体约 0.476 GiB，建表 frontier 等另计；先确认最大距离，再决定压缩格式。重叠 PDB 取最大值，未经动作成本分摊证明不得相加。当前不将新 PDB、Tail-9/10、全层 TT 或工作窃取重写列为本轮必做。

收益门槛均是项目目标：加载/复用希望明显减少初始化；纯热路径期望至少约5%稳定改善，复杂方向/dual策略希望约10%改善以抵消维护成本；直接相关个案不持续退化超过5%。噪声或收益不足则保留开关/回退，停止扩大该项。两实拍只支持个案结论，不报告总体成功率或小样本 p95。
