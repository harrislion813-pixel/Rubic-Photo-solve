# 求解器强优化行动方案：以三阶 QTM 严格最短证明为主线

日期：2026-09-28。基于提交 `16aca9f009db15778f842cab133b3137158476da`。

本文件是交给实施 AI 的任务书，不是优化完成报告。本轮完成了代码审查和 HTM/QTM 共 48 次基线运行，尚未修改求解器。所有实施任务均未完成。

用户要求是**强优化**。QTM 专用完整 PDB、强联合 PDB、QTM Tail、按 QTM 优化的原生候选生成器和搜索内核改造都是主线交付，不能只做奇偶剪枝、编译参数或缓存便宣告完成。低内存兼容配置可以保留，但不能代替强配置的实际建表、接入与验证。

旧 `docs/ai-htm-qtm-implementation-guide.md` 中“首版不要求 QTM 三阶大型表”描述的是已经完成的功能首版范围；本次优化按用户最新要求和本文件执行。

## 1. 要实现的结果

维持三阶完整最优搜索及现有 HTM/QTM 定义，显著缩短 QTM 的独立最短性证明时间，同时缩短首次可执行解的等待时间。分别评估这两项，不能用更快返回未证明候选冒充严格求解加速。

交付两种资源配置：

| 配置 | 资产与用途 | 交付要求 |
| --- | --- | --- |
| 标准配置 | QTM 完整 Corner/Phase-1 PDB、小表、Tail-7，选择性 Edge PDB | 必须构建、测试；供内存较小的机器使用 |
| 强配置 | 标准配置加三轴 `twist/flip/UDSliceSorted` 强联合 PDB、Tail-8、原生 QTM 候选器和改造后的内核 | 本次主要验收对象；必须实际构建、接入和测量 |

性能目标是实施验收目标，**不是已经测得的加速承诺**：

- 冻结验收集中，基线和新版均可完成、且基线证明耗时 ≥0.1 秒的 QTM 样本，配对耗时比的几何平均目标 ≥5 倍；若交集不足 10 个，应扩大有真实证明的样本，不能靠筛选简单样本达标。
- 完整验收集固定 60 秒预算，目标证明成功率提升 ≥25 个百分点；若基线成功率已超过 75%，目标为剩余超时数量至少减半。
- 含全部超时样本的 PAR-2 指标至少改善 2 倍：每个超时记作 `2 × timeout`，完成记实耗时。把它称为综合指标改善，不能称为真实平均加速比。
- 固定候选与相同已排除预算的对照中，困难样本生成候选数几何平均目标减少 ≥5 倍。不同完成深度的超时运行不能直接比较总节点数。
- HTM 的代表性耗时指标回退不超过 10%；二阶继续使用现有双模式准确表，避免在本轮重复改造。
- 强配置求解进程峰值工作集目标 ≤8 GiB，单个建表任务峰值提交内存目标 ≤12 GiB；内存指标、磁盘空间和建表耗时均需实测。
- 端到端候选验收集目标：热服务首次有效候选 p95 ≤1 秒、3 秒时 QTM 候选代价中位数低于旧 HTM 候选重计价结果。若未达标，记录差距并继续优化。

若强配置做完仍未达到目标，应继续依照剖析结果迭代或如实标明目标未达成，不能把目标改低后声称完成。极难的 25/26 步状态保留为独立压力组，不承诺全部在 60 秒内完成证明。

## 3. 正确性约束

1. 生产严格搜索继续使用全部 18 种动作，QTM 成本为 `1/2/1`。建表/oracle 可用 12 个单位成本的正反 90° 动作，但必须允许连续同面，否则 `R R = R2` 会被删掉。
2. HTM 下界可用于 QTM，因为 `h_HTM ≤ d_HTM ≤ d_QTM`。不得乘以经验系数；不得把未经成本分摊证明的多个 PDB 相加。默认取最大值。
3. 只有完整排除、更强的合法下界或准确表查询能推进证明。超时、取消、方向采样、未穷尽任务队列不构成完整排除。
4. 两阶段候选器只给上界。进入 Phase-2 后的限制搜索即使失败，也不能排除全部 QTM 路径；严格搜索仍允许离开该子群。
5. PDB 的坐标变换必须与完整 cubie 动作一致。整体旋转可用于启发式/候选映射，但三阶输出必须复原用户固定面向；不能直接套用二阶“整体旋转视为同解”的定义。
6. 部分 PDB 必须区分已知准确距离与未覆盖项。只有确实完整覆盖到半径 `r`，未覆盖项才可作为 `r+1` 下界；不得作为准确距离恢复公式。
7. PDB/Tail 的 metric、坐标版本、覆盖范围、完整标记、校验和都必须核验。不能靠文件名猜模式；不能把 HTM Tail 的距离直接当 QTM 距离。
8. TT 必须比较完整状态键和后继约束上下文；哈希指纹碰撞不能造成错误剪枝。只缓存完整搜索失败的剩余代价。
9. 每个返回公式都按原状态执行，并重新核对 QTM 代价。预算不足、超时、取消时维持未证明状态。

### Q1：模式化资产与 QTM 奇偶预算

**修改位置：** `native/include/solver.hpp`、`native/include/pdb.hpp`、`native/include/tail.hpp`、`native/src/{solver,pdb,tail,main}.cpp`、`cube_app/{native,optimal,tables}.py`、`server.py`。

- [ ] 将 metric 定义放到无循环依赖的公共接口，建立不可变的 per-request `MetricSearchContext`。转移表可共享，距离表和 Tail 按 metric 选择；HTM/QTM 交替请求不得修改共享全局模式。
- [ ] 新格式支持明确的 metric、pattern、coordinate-version、encoding、entry-count、coverage、max-distance、complete、checksum。保留旧 HTM v2 读取器，新 QTM 使用独立文件与版本。
- [ ] 建立启发式“支配”判断：同抽象下完整 QTM PDB 可覆盖相应弱表；完整 HTM 大表并不自动支配 QTM 小表。测试混装、缺表、部分表与损坏表。
- [ ] 用角排列奇偶性 `p(s)` 推出 QTM 解代价模 2。预计算角排列 parity 或在转移中增量维护，不能每节点物化 cubie 再计算。
- [ ] 对合法下界做 `h = h0 + ((h0 XOR p(s)) AND 1)`；根预算起点对齐 parity，后续步长 2。子节点 parity 随四分之一转翻转、随半转保持。
- [ ] 维护独立的 `proven_through`，不要把 `for depth += 2` 的循环值直接当完成深度。例如偶状态完整排除 ≤16 后，奇偶性同时排除 17；正在搜索 18 时取消，仍不能宣称排除了 18。
- [ ] 初始合法下界、用户预算截断、候选代价 `U` 与 parity 一起推导证明条件；验证 `R2` 的预算 0/1/2、奇/偶候选、动态更新及缓存重试。
- [ ] 更新 proof 版本与能力握手，同步 `main.cpp`、Python、服务、基准和发布预检；缓存只接收新版本可验证的连续排除区间。

**完成条件：** 含奇偶跳层的原生/回退输出与独立 oracle 一致，超时/取消/cache 的证明语义通过专项测试。本阶段只是铺路，不能作为本次优化终点。

### Q3：强联合 PDB——本方案的核心必做项

**修改位置：** `native/include/{cube,symmetry,pdb,solver}.hpp`、对应 `.cpp`；可新增 `strong_pdb.cpp`、`strong_symmetry.cpp`。

联合抽象必须保留角朝向、棱朝向和四条指定 slice 棱的**位置及相对排列**。先定义完整投影及目标集合，再写索引。不能把当前 `canonical_index` 简单乘 24 后当新表。

- [ ] 定义 `UDSliceSorted = combination(12,4) × permutation(4)`，共 11,880 原始坐标；实现 rank/unrank 和 18 动作转移，并与完整 cubie 逐项对照。
- [ ] 实现适用于该坐标的 16 对称群商、代表元、回代表元映射及稳定子；按标准定义预期约 788 类，类数必须由枚举验证，不能为了匹配常数丢状态。
- [ ] 变换 joint 坐标时，twist/flip 必须与 slice 使用同一对称映射；尤其 flip 的变换需要结合 slice 信息，不能直接搬旧独立 flip 共轭表。
- [ ] 正确处理一个代表元的多个稳定子，确保所有等价 twist/flip 槽具有同距离。验证投影动作与商图动作可交换，证明完整态解路径投影后仍到达抽象目标。
- [ ] 若采用 788 类布局，表项数为 `788 × 2048 × 2187 = 3,529,433,088`。首个可靠版本用 1 byte/项，约 3.29 GiB；坐标可能可用 uint32，但乘法、字节偏移、循环和文件大小一律用 uint64/size_t，避免有符号 32-bit 溢出。
- [ ] 构建完整 QTM 精确距离，动作仍为 12 个 quarter-turn。初版严禁直接移植 HTM 的模 3 距离跟踪：QTM 半转成本为 2，相邻宏动作的距离变化不能按 ±1 唯一还原。
- [ ] 构建器必须支持分层检查点、可靠恢复、并行访问和校验。大前沿使用 bitset 或有内存上限的分块队列，避免旧 frontier、各线程 next、合并 next 同时占用数倍状态 ID 空间。
- [ ] 恢复时核验构建参数、源版本、坐标版本和已完成层；中断中间层不可宣称该层覆盖完成。最终资产通过完整校验后原子替换目标文件。

## 5. 内存、磁盘与构建策略

下表为根据表项数和当前紧凑结构计算的容量估计，运行/构建峰值必须实测。它们用于安排实施，不是测量结果。

| 资产 | 不压缩距离/存储规模 | 实施约束 |
| --- | --- | --- |
| QTM Corner | 84.1 MiB（1 byte/项） | 确认最大距离后可压缩，先保准确性 |
| QTM Phase-1 | 134.4 MiB（1 byte/项） | 三轴复用一张表 |
| 两组 QTM 六棱块表 | 合计约 81.2 MiB（1 byte/项） | 仅在收益大于额外计算/内存查询时启用 |
| QTM 强联合表 | 约 3.29 GiB（1 byte/项） | bitset/分块前沿，避免巨型 vector 多份复制 |
| QTM Tail-7 | 约 200 MiB，取决于槽位/Bloom | 约 920 万状态，独立实测 |
| QTM Tail-8 | 约 1.6–2.0 GiB，取决于槽位/Bloom/布局 | 约 8605 万状态，精确键不可省略 |

强配置这些主体数据合计约 5–6 GiB，另需转移表、对称映射、线程 scratch 和操作系统页缓存。按当前 32 GiB 机器，先把构建并发设为一次一张大表，峰值预算 12 GiB，工作磁盘预算预留 50 GiB。运行前重新查询实际可用资源，采用 `min(12 GiB, 可用物理内存的 70%)` 作为构建硬上限。

强联合表可以先用 byte 距离 + 两个 frontier bitset，主体约 `3.29 + 2×0.41 GiB`，再加转移与线程缓冲；这是避免十几 GiB 状态 ID 队列的可执行起点。并行 bitset 更新需原子/分块所有权，避免漏位。建表后期可测未访问槽反向扫描，保持逐层同步与稳定子传播。

若内存不足，优先缩小批次、减少线程、使用分区磁盘队列/映射和断点恢复；资源不足是需要记录的真实约束，不是把强表从必须交付项删除的理由。先预生成标准表，再生成强表，不要求每次开发回归重建全部资产。

## 6. 基准矩阵和验收口径

逐阶段保持其他条件一致，至少保存：

| 组别 | 配置 | 用来回答的问题 |
| --- | --- | --- |
| B0 | 冻结的当前版本 | 真正历史基线 |
| B1 | B0 + parity/模式化资产 | 规则层收益多少 |
| B2 | B1 + QTM 完整基础 PDB | 模式专用下界收益多少 |
| B3 | B2 + 强联合 PDB | 大表是否减少整体证明成本 |
| B4 | B3 + Tail-7；再 Tail-8 | 准确末段表的空间/速度收益 |
| B5 | B4 + 内核与线程池 | 单节点成本与并行效率改善多少 |
| B6 | B5 + 原生动态 QTM 候选 | 整体用户等待与上界改善多少 |
| E | 分别开关 Edge/TT/方向/PGO | 附加策略是否值得默认启用 |

执行约定：

1. 开发 smoke：现有 8 状态、4 线程、2 秒、3 次重复；它只用于快速找退化。
2. 核心验收：48 状态、4 线程、60 秒、3 次重复；完成耗时对照不足 10 状态时，用有依据的已证明状态扩充并冻结。基线/候选构建顺序交替。
3. 线程验收：固定代表性子集，1/4/8/16 线程；深度与候选相同。生产线程数由总耗时和候选资源竞争决定。
4. 端到端：相同 32 个随机合法状态，热服务 3 秒候选质量测试与 60 秒完整请求测试；另独立测新进程首次请求和资产初始化。
5. 精确比较搜索规模：用显式 `max_cost` 完整排除同一预算；对照未能排完时报告 censor，不把该部分总节点与完整排除的节点比值称为剪枝倍数。
6. 4 个极难状态单列，报告下界推进、候选成本、超时和内存。统一状态定义，尤其不可把 superflip 与 superflip+fourspot 混为一个状态。
7. 报告每状态重复的中位数、全样本 p50/p95、成功率、PAR-2、工作集峰值和提交内存峰值；少量重复的 p95 需说明样本规模。冷进程且磁盘缓存未清空，应明确标注。
8. 48×3×60 秒的单配置验收最坏约 2.4 小时，完整矩阵可能跨多小时；这是强优化的必要离线成本。先 smoke 筛掉明确退化策略，再对最终候选做完整验收，避免无意义重复全矩阵。

## 10. 算法依据与适用范围

QTM 的置换奇偶性和半径 7/8 球计数来自研究者公开的 [God’s Number is 26 in the Quarter-Turn Metric](https://www.cube20.org/qtm/)。本方案的球累计值由其中逐层数量相加得到；不能把 26 的全局上界当成个别状态的最短性证书。

强联合表的坐标结构、对称商规模和稳定子问题参考作者的 [Pruning Tables](https://www.kociemba.org/math/pruning.htm)。本文 3.29 GiB 是按其结构的表项数乘以 1 byte 推算；QTM 距离要在本项目重新生成。该文描述的 HTM 模 3 跟踪不能直接套到本方案的 QTM 半转宏动作。

三轴最大值和三轴加强思路参考 [The Optimal Solvers](https://kociemba.org/math/optimal.htm)；其中其他实现的历史性能倍数不作为本项目的实测收益。大表下界结合 IDA* 的方法背景见 Korf 的原论文 [Finding Optimal Solutions to Rubik’s Cube Using Pattern Databases](https://aaai.org/Papers/AAAI/1997/AAAI97-109.pdf)。本方案的优先级和资源配置来自当前代码与本轮基准分析。
