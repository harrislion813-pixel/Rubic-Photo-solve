本设计落实 [HTM 评审](htm-speed-review-2026-10-05.md) 中与 P0/P1/P2 并行推进的强表设计里程碑。当前交付是坐标、资源、构建及验收设计；尚未生成 HTM 强表，也没有这张表的性能成绩。

**坐标及度量。** 新增 HTM 独立 `SortedSliceSymmetry`，投影为切片组合及四条切片棱排列、所有棱翻转、所有角朝向。切片原始坐标为 `495×24=11880`，16 个对称下有 788 类，索引为 `(class×2048 + conjugated_flip)×2187 + conjugated_twist`。原始资料给出 3,529,433,088 项和最大 HTM 距离 13；这些是设计依据，仍须在本项目重新枚举和验证。[剪枝表原始说明](https://kociemba.org/math/pruning.htm)

对称变换的 flip 不得只用现有普通 Phase-1 flip 表：它依赖 sorted-slice 的排列信息。实现可参考 `native/qtm/strong_coords.*` 中的仿射 flip 映射、类代表和 stabilizer，但 HTM 代码、格式和资产必须独立。生成阶段必须为有稳定子群的代表填入全部等价 twist/flip 项，否则会高估距离。先实现 reference 查询，再逐项核对优化查询。

所有 18 个 HTM 动作，包括半转，成本均为 1。不能采用 QTM 构建器仅 12 个四分之一转的 BFS，也不能修改 QTM 表头后加载其距离。运行时将新表与已有下界取 `max`；保持现有 Phase-1 的同值加强，不能把该加强直接套到新强表上。三轴强表查询作为单独后续消融，不与首版单轴实现混入。

**资产及回退。** 建议字节构建格式 `assets/htm/strong-v1/strong_sorted_htm_v1_byte.pdb`，验证后发布 nibble 格式 `strong_sorted_htm_v1_nibble.pdb`。表头单独携带 metric=HTM、坐标版本、builder 版本、维度、实际最大距离、完成层、unknown_count、编码位宽和完整性校验；不要沿用 QTM 版本和路径。字节格式用 255 表示未知，部分表的未知查询只能返回可靠完成层的下一层下界；如果不能可靠证明覆盖范围则回退。

只有完整覆盖、独立全表证书和逐项压缩回放通过后，才允许将表标为 complete。nibble 保留 15 为未知/无效码，最大值必须不超过 14。缺表、部分表、版本错误、校验失败时，保留现有 HTM 轻量配置。用户选择的强配置才能加载此资产；轻量安装清单及默认包不增加它。加载的校验、工作集与实际采用耗时都纳入原请求期限。

**资源预算。** 以下是固定容量估算，不能称为实测峰值。

| --- | ---: |
| 距离字节数组 | 3,529,433,088 B，约 3.287 GiB |
| 两个 BFS frontier 位集 | 共 882,358,272 B，约 0.822 GiB |
| 压缩成品主体 | 1,764,716,544 B，约 1.644 GiB |
| 18 动作的 class×flip/twist 转移主体 | 约 114.6 MiB |

| 构建最低规划预算 | 约 4.61 GiB，仍需记录实际峰值 |

初版用字节原子 claim 和共享 frontier 位集；不为每个 worker 复制 3.29 GiB 的距离表。开始前将配置上限与可用物理内存的 70% 取较小值，预算不足时在分配大数组前退出。线程共享表，按 frontier word 分工。18 动作转移规模与 QTM 的 12 动作转移不同，不能照搬其资源日志。

磁盘应至少为“上一完整 checkpoint、临时新 checkpoint、最终 nibble”保留约 8.22 GiB，再给日志和 header 留余量。采用 64 MiB 分块 I/O 和校验。整个构建完成后再流式压缩，避免同时持有完整 byte 和 nibble 数组；保留恢复用 byte 文件时，总资产体积也必须单独报告。

**断点及证书。** 完整 BFS 层结束并 join 全部 worker 后，才写 checkpoint；不能用活动层快照恢复。写到临时文件，完成 payload、checksum、coverage、unknown_count 后原子替换。恢复时核对 HTM metric、坐标/builder 版本、完整文件长度和校验，然后扫描距离数组重建 frontier；拒绝大于 completed layer 的非未知距离。中断后保留上一完整 checkpoint。

全表验证应检查解态零距离、唯一零距离投影、未知数为零、稳定子等价项相同、每个非零项有一步递减邻居、每条 HTM 转移满足 `|d(s)-d(m(s))|≤1`，并输出实际距离直方图。压缩后逐项等于 byte 源。浅层独立 cubie BFS 至少到深度 4，随机合法状态上 reference 索引与快速索引一致；有版本/损坏/部分表专门回退测试。

**后续执行顺序。** 先提交坐标与浅层 oracle；再实现有内存上限和断点恢复的 byte 构建器，完成全覆盖及证书；随后流式压缩、可选加载和默认轻量回退；最后固定 15 总额度，运行六照片状态及独立冻结随机状态的新旧请求矩阵。分别报告节点减少、每节点成本、首候选、采用时刻、严格完成率、PAR-2、启动/加载、CPU、峰值工作集和下载体积。该路线有更强下界的依据，但其他实现的加速倍数不能作为本项目成绩。[最优搜索原始说明](https://kociemba.org/math/optimal.htm)
