# 性能重构交付记录

依据 `performance-review-2026-09-27.md`，先交付已有实测依据的优化、可验证的任务生命周期，以及独立的二阶全状态表。HTM 严格最短保证保持不变。

## 已实现

- 新增长期维护的 `tests/benchmark_native.py` 与固定验收集。记录冷启动、热搜索、固定状态、候选解、编译参数/源码哈希/EXE 哈希、PDB 哈希、超时前完成深度、进程内存峰值及逐层/实时事件。轮换配置顺序；p50/p95 的全样本时间和仅成功证明时间分开汇总，超时样本不删除。
- 三个独立 Phase-1 轴值相等且非零时，下界增加 1；角块下界不参与相等判断。完整 PDB 覆盖其小投影时跳过小表，缺失或部分覆盖仍保留小表。策略在每次求解开始时固定。
- 候选扩展逐轴计算和判界，通过三轴及角块剪枝后才更新棱排列。搜索状态只保留坐标、48 位棱排列及可选 Edge 坐标；完整角/棱排列与朝向只在 Tail、额外 Edge PDB 或 TT 使用时物化。
- 新增生成候选数、各 PDB 查询数、逐轴/相等规则/角块/棱块拒绝数，以及每线程当前迭代的节点/候选/工作/等待时间。线程本地计数分批汇总，250 ms 的搜索快照不把进行中的深度标记为已完成。累计统计包含方向预选，节点与候选定义分别保留。
- 原生优先启动，短时探测与后续证明属于同一任务；困难状态并行生成上界，原生为其预留一个线程。上界控制消息验证动作后接收，在下一次深度迭代开始时使用，不打断已经进行的深度。
- 原生协议 v2 包含请求 ID、取消及更新上界。正常取消会等待终态帧，保留常驻进程；只有异常进程停止或取消 5 秒内无响应才关闭服务。旧 EXE 会明确报告协议不兼容，不能把文件存在当作初始化成功。
- 有限/无限超时统一路由到原生；排队、初始化、搜索及回退共用绝对 deadline。任务状态包含实际引擎和回退原因，原生失败记录日志；原生超时不会再次启动 Python 搜索。
- 同一活动 facelets/HTM/最大深度/证明版本去重。原生进程内保存最多 128 个规范化状态的已完成排除深度；PDB 与证明规则在该进程内不可变，重启清空缓存。未完成深度不复用，不保存未完成搜索前沿。旧五字段基准协议关闭该缓存。
- 坐标转移及小剪枝表保存为 `coordinates_htm_v1.bin`，带版本、大小和全数据校验；可通过 `CUBE_NATIVE_COORDINATE_CACHE` 指定位置或空值关闭。损坏缓存安全重新构建，写入采用临时文件和替换。
- 二阶规范化到固定 DBL 角块，反向 BFS 覆盖 3,674,160 个状态，准确距离的最大值为 11。按距离递减选动作，映射回原用户面向并验证。字节距离加转移表约 3.60 MiB，带版本及 SHA-256 持久缓存，支持离线预生成。
- 扩展 PGO 训练脚本，加入独立随机合法状态，使用线程安全的 profile 更新；保留未用于训练的验收状态。此次普通构建不使用 PGO。

## 验证与基准

浅层 BFS 回归覆盖全部深度 ≤4 的 46,741 个三阶状态，逐一核对下界不超过准确距离、紧凑状态转移与完整状态一致、不同 cutoff 下分阶段剪枝与完整求值一致。缺表及部分 Corner/Phase-1 PDB 使用独立回归。

生命周期测试覆盖无限时原生路由、排队时间计入预算、取消不等待调度锁、回退不重置预算、活动任务去重、原生取消后保留 PID、重试复用完成深度，以及不同线程数和逆向求解。二阶回归包括随机状态在全部 24 个用户面向下的动作映射和缓存损坏重建。

三项固定状态，每个配置重复 3 次，16 线程、完整 Corner/Phase-1 PDB、Tail-6，GCC 16.1.0 相同普通 O3/LTO 构建。配置顺序交替；候选解固定，关闭证明缓存复用。27 次运行全部完成严格证明，动作全部重新执行验证。

|---|---:|---:|---:|---:|

默认分阶段相对仅剪枝配置也有收益，因此启用为默认；独立关闭开关仍保留。这是同一新核心的开关对照，关闭优化配置仍包含紧凑状态及统计，不是审查前的历史 EXE。新进程启动中位数 0.671 秒，文件系统及辅助表缓存为热；进程工作集峰值约 328.7 MiB。未锁定频率，样本数量较少，不能外推所有合法状态的速度。

元数据与 p50/p95、超时比例、完成深度汇总保存在 `performance-refactor-benchmark-2026-09-27.json`；全部原始事件在 `.cache/native-refactor-benchmark.json`，长期维护的脚本和固定输入已加入 `tests/`。完整 Python 回归为 **46 passed in 52.92s**；随后追加的固定基准/训练输入合法性、原生启动失败，以及任务生命周期/API 回归为 **14 passed in 3.62s**（其中 12 项与完整回归重叠，共 48 项不同测试）。四组前端 Node 测试、Ruff、compileall、C++ clang-format 和 git diff 检查均通过，原生 EXE 已重新编译。

另对 8 个状态执行默认配置 2 秒预算验收，14/16 步样本完成；其余 6 个样本保持 timeout，绝不标记为最短。其中三个独立随机合法状态均完整排除至 16 步，superflip 样本完整排除至 16 步；进行中的深度未计入已完成证明。此短预算检查用于验证超时统计和数据完整性，不是深度 19/20 的完整性能验收。数据与超时样本的汇总也纳入上述 JSON，原始事件在 `.cache/native-refactor-acceptance.json`。



## 仍按评审保留为实验项

强 `twist/flip/UDSliceSorted` 联合 PDB 需要新的对称坐标、稳定子处理和大规模建表方案，本次没有用现有索引乘 24，也没有生成或启用未经验证的新表。工作窃取、长期线程池、Tail-7、更多 Edge PDB、选择性 TT、模 3 压缩和软件预取同样维持实验优先级；当前交付提供它们需要的统计与对照基础。默认保留现有线程调度、Tail-6、正逆方向预选和关闭的 TT。对称映射辅助表的持久化与前端事件推送可独立继续，当前仍使用只读内存映射 PDB 和轮询。

验收集含已在本项目证明的 16/17/18 步状态以及满足朝向和奇偶约束的固定随机合法状态。尚未完成更大规模的深度 19/20 状态证明，不以打乱长度充当最短深度，也不把本机小样本收益外推到所有状态。
